# 人生支线 八小时 MVP 项目书与前端集成文档

负责人：软工 A，承担前端与集成协调。本文同时是四人共享的项目书和产品范围依据。

配套文档：[艺术 UI](02-艺术UI-视觉与交互交付.md)、[硬件](03-电子信息-硬件与串口协议.md)、[后端 AI](04-软工B-后端AI与接口契约.md)。所有人先读本文第 1—5 节，再读自己的文档。HTTP 字段以文档 04 为准，串口字段以文档 03 为准。

本包是新的八小时执行方案。与上一级概念方案不一致时，以本包为准：采用摇签结构，不做开门结构；先用电脑浏览器和 USB 串口展示，手机适配为加分项。

## 1. 产品项目书

### 1.1 产品定位

「人生支线」是一座桌面赛博寺庙。用户写下已经做出的选择与放弃的选项，实体签筒摇动，AI 根据背景生成未选道路上的一段可能经历。用户在支线中继续选择；当某个行动可能背离初衷时，系统邀请用户“回望”。最后带走一张平行人生收据。

硬件形态：橡皮泥装饰的寺庙模型、可摇动的轻质签筒、ESP32S 和 TFT。长故事在电脑网页展示，TFT 展示寺庙画面和固定重要短句。

三分钟演示需要让观众看懂三件事：实体摇签与数字推演联动；未选道路会继续产生选择；劝解帮助用户重新找回原本目的。

### 1.2 已有资源与工作假设

- 团队四人：艺术同学负责 UI 与视觉，电子信息同学负责硬件，两位软工分别负责前端集成、后端 AI 与串口桥接。
- 总开发时间八小时，从共同启动的 H0 计时。
- 有电脑、USB 数据线、可用的 AI 服务凭据及网络，最迟 H0.5 核实；凭据由后端使用。
- 器件：SG 舵机、电机、ESP32S 开发板、TFT、SD 卡及模块、12V 锂电池、音频功放。确切型号、驱动器、降压电源及线材由硬件同学在 H0.5 前确认。
- 已确认团队熟悉前端 + Java。默认技术：React + Vite + TypeScript 前端，Java 17 + Spring Boot 3.x 后端，Arduino ESP32 固件。前端若更熟悉 Vue，可在 H0.5 前替换，保持 HTTP/串口契约不变；Java 使用成员已有且可运行的模板，不安排现场学习新框架。
- 技术选型和工期是规划，尚未实机验证；缺器件时按文档 03 明确降级，不能声称硬件功能已完成。

### 1.3 P0 必须完成

| 能力 | 最小实现 | 完成证据 |
| --- | --- | --- |
| 表达选择 | 四个输入：背景、已选道路、未选道路、在意的目标 | 自定义内容能提交并传到后端 |
| 实体仪式 | 一次提交触发一次短时摇签，随后自动停止 | 连续三轮，无重复摇动和板卡复位 |
| TFT 展示 | 寺庙静态图；问签、支线、回望、归来固定短句 | 真实屏幕可读，至少一次状态联动 |
| AI 支线 | 一次生成：开场、一个二选一节点、两个对应后续与收据草稿 | 内容包含输入背景，JSON 通过校验 |
| 回望劝解 | 在适用的选项上展示目标、可能后果、替代行动 | 固定演示案例能够触发；普通选择不一律判错 |
| 人生收据 | 已选/未选道路、发现、现实中的下一步 | 用户可编辑发现与行动，下载 `.txt` |
| 可控演示 | 明确标注的预置案例模式、重置按钮、设备状态 | AI 不可用仍能演示预置案例；不伪装实时生成 |

### 1.4 这八小时不做

账号、数据库、跨天记忆、完整人物画像、多层无限分支、延迟解锁、自动打印、连续出签、语音识别、敲击识别、3D 网页、支付、移动端扫码配对、设备联网、多用户并发、自动判断所有人生选择是否正确。

SD 卡、音频、12V 电池不是本次必须项。模型用橡皮泥做静态装饰，运动结构使用轻质签筒和独立支架。

## 2. 唯一主流程

```text
填写四项背景 → 提交并摇签 → 等待 AI
→ 展示未选道路的开场 → 用户在支线内选择 A / B
→ 展示对应后续；必要时出现回望
→ 接受当前走向，或改选另一个选项
→ 确认并编辑收据 → 下载 → 重置迎接下一位
```

初始真实选择与支线内的 A/B 是两个层级，UI 必须分别标明。原型只要求用户填写“已经选择”的事情，暂不开发“正在犹豫”的第二入口。

“改选”只允许在这一个 A/B 节点切换，使用已经生成的另一结局，不再调用 AI。完成收据后如需重新体验，清空会话再开始。

网页状态：`input → generating → ready → reflecting / ending → complete`；生成或服务失败进入 `error`。设备离线只影响硬件状态，不把网页故事改成失败。

## 5. 固定演示案例与验收

预置案例 ID：`team-project`。

- 背景：朋友邀请我参加两天项目，我担心自己能力不足，每天只能投入两小时。
- 已选道路：拒绝邀请。
- 未选道路：接受邀请，负责一个小模块。
- 目标：希望参与合作，也不想耽误队友。
- 支线节点：任务遇到困难；A 为一直隐瞒进度，B 为说明困难并协商范围。
- A 触发回望：隐瞒可能让队友更难安排；替代走法是及时说明并缩小任务。
- B 展示另一种可能后续，不保证队友一定理解或项目一定成功。
- 收据强调：仍然可以尝试与他人协作，现实中可询问一个适合自己的小任务。

验收清单：

- [ ] 自定义输入能得到一份通过校验的真实 AI 结果；至少验证三个不同背景。
- [ ] 预置案例 A 可回望、可改 B，收据与最终选项一致。
- [ ] 连点提交只产生一个会话、一个 DRAW 动作。
- [ ] TFT 状态能对应生成、故事、回望、完成；实际中文或图片可读。
- [ ] 模型摇签结构连续三轮稳定，停止命令和超时停止有效。
- [ ] AI 超时或格式错误显示明确错误；切预置案例须用户明确选择。
- [ ] 拔掉 USB 后网页仍能完成故事，显示设备离线；重连不补摇历史动作。
- [ ] 收据可编辑、下载，下一位体验者看不到上一个人的输入。
- [ ] 记录哪些是实机通过、哪些是模拟通过；所有未完成项如实列出。

## 6. 软工 A 的实现任务

### 6.1 技术与页面

使用 React、Vite、TypeScript、普通 CSS。用 React 本地状态管理即可，不额外引入全局状态框架。开发时 Vite 将 `/api` 代理到 B 的本地服务；演示优先同一电脑浏览器，后续可由后端托管 `web/dist`。

组件建议：`IntakeForm`、`RitualWaiting`、`BranchStory`、`ReflectionCard`、`ReceiptEditor`、`DeviceBadge`。组件名可改，HTTP 字段不可自行改。

输入上限按文档 04：背景 400 字符，已选与未选各 100，目标 150。预置案例按钮自动填入并锁定对应背景，页面持续显示“预置案例演示”。切回自定义时使用 `mode: live`。

### 6.2 调用方式

1. 页面打开调用 `GET /api/health`，显示后端与设备状态。
2. 提交用 `POST /api/sessions`，保存返回的 `id`；按钮立即禁用。
3. 在生成阶段每秒请求 `GET /api/sessions/:id`；结束后停止故事轮询。设备状态可每两秒通过 health 更新。
4. 点选 A/B 调用 `POST /api/sessions/:id/choice`，以服务端返回的状态更新页面。
5. 收据编辑好后调用 `POST /api/sessions/:id/receipt`，确认成功再允许下载。
6. 新体验调用 `POST /api/reset`，成功后清空输入、定时器、故事和下载数据。

不自行发送硬件命令，也不在浏览器持有 AI 密钥。设备状态来自 B，不把命令已发送显示成电机已经完成。

### 6.3 回望与收据 UI

当选项有 `reflection` 时，展示 `goal / concern / alternative` 三段。按钮为“换一种走法”和“保留当前走向并整理收据”。换一种走法选择另一个 optionId，不请求新故事。

无回望时也展示该选项的后续，再进入收据确认。收据中的 `insight` 和 `nextStep` 可编辑；已选/未选道路来自原输入，不能误用支线内 A/B 文案。

收据以文本 Blob 下载，UTF-8 文件名可用 `人生支线收据.txt`。截图、PNG 导出和海报分享只作为 P1。

### 6.4 错误与限制

- 请求失败保留用户输入，展示简短提示，不自动重复创建会话。
- 创建请求响应丢失时，可用同一个 `requestId` 重发以获取原会话。
- 生成失败后提供“重置后重试”和“切换到预置案例”，后者明确替换为案例背景。
- `409` 提示先结束/重置当前会话；`404` 提示服务已重启、需要重新开始。
- reset 或页面卸载时清除轮询，旧响应不应覆盖新会话。
- 故事和用户输入用文本渲染，不直接执行模型生成的 HTML。

## 7. 对接交付与停止条件

H1 前从 B 拿到快照 JSON 与类型；从 UI 拿到低保真和色板。H2 前必须用实际接口触发一次实机动作，避免最后一小时才联调。

A 向团队交付：可运行网页、启动说明、三分钟操作顺序、验收记录。完整闭环稳定且 P0 达成后停止扩展。H6 后只修阻断演示的问题。

建议演示节奏：20 秒介绍与输入、20 秒摇签与生成、50 秒支线选择、40 秒回望及改选、30 秒收据、20 秒说明实现与边界。真实生成超时就如实切到预置案例，不伪装成实时 AI。

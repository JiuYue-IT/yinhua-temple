后端已经完成，可以直接联调。本文档说明怎么启动后端、怎么调接口，以及几个容易踩的坑。
字段的权威定义仍以 `docs/04-软工B-后端AI与接口契约.md` 为准；TypeScript 类型可以直接复制 `contracts/types.ts`。

## 0. 先看这三条

1. **真实 AI 生成要 15—20 秒**，后端最多等 30 秒。等待页不要显示假进度；前端轮询时**不要**设置比 30 秒短的总超时。
2. **所有错误体格式统一**：`{"error":{"code":"...","message":"..."}}`，`message` 已经是给用户看的中文，可以直接显示。
3. **只有一个活动会话**。完成、失败或刷新页面之后，要开始新体验都必须先 `POST /api/reset`。

## 1. 启动后端（5 分钟）

需要 **JDK 17**（`java -version` 显示 17 即可），不需要装 Maven。

```powershell
cd server
Copy-Item config.example.env .env     # 只用预置案例的话，不改内容也能跑
.\mvnw.cmd spring-boot:run            # 第一次会下载依赖，需要联网
```

启动成功时会显示：

```
==================== 人生支线后端已启动 ====================
  接口：http://localhost:8080/api/health
  AI  ：未配置，只能使用预置案例 ...
  设备：dryrun 模拟（不连接硬件）
```

- **没有 AI 密钥也能完整开发**：预置案例 `team-project` 能走通全部流程（含回望、改选、收据）。
- 需要测真实 AI 时，找软工 B 在演示电脑上配置 `.env`。**密钥不在压缩包里，也不要放进前端代码。**
- `设备：dryrun` 表示没接硬件，后端只记录事件，`health` 返回 `device.status = "dryrun"`。

验证：浏览器打开 <http://localhost:8080/api/health>，能看到 JSON 就说明后端正常。

## 2. 前端怎么连后端

### 开发时：Vite 代理（推荐）

`web/vite.config.ts`：

```ts
export default defineConfig({
  plugins: [react()],
  server: {
    proxy: { '/api': 'http://localhost:8080' },
  },
});
```

前端代码里一律写相对路径 `/api/...`，不要写死 `http://localhost:8080`。

> 没配代理、直接跨端口调用也可以：后端已允许 `http://localhost:*` 和 `http://127.0.0.1:*` 的跨域请求。

### 演示时：后端托管（单端口）

```powershell
cd web; npm run build                 # 产出 web/dist
cd ..\server; .\mvnw.cmd spring-boot:run
```

打开 <http://localhost:8080/> 就是前端页面，前端代码不需要任何改动。

- **前端目录必须叫 `web/`，和 `server/` 同级**，后端会去找 `../web/dist/index.html`。
- 目录不同时，用环境变量 `WEB_DIST` 指定。
- **只用单页状态切换，不要引入前端路由**（例如 `/receipt` 这类路径）。后端只托管静态文件，刷新子路径会 404。

## 3. 接口一览

| 方法 | 路径 | 用途 | 成功返回 |
| --- | --- | --- | --- |
| GET | `/api/health` | 服务 / AI / 设备状态 | `Health` |
| POST | `/api/sessions` | 提交并开始（会摇签） | **202** + `SessionSnapshot` |
| GET | `/api/sessions/{id}` | 轮询当前状态 | 200 + `SessionSnapshot` |
| POST | `/api/sessions/{id}/choice` | 选 A / B，或改选 | 200 + `SessionSnapshot` |
| POST | `/api/sessions/{id}/receipt` | 确认收据 | 200 + `SessionSnapshot` |
| POST | `/api/reset` | 清空，迎接下一位 | 200 `{"ok":true}` |

**成功响应没有 `data` 外层**，直接就是快照对象。完整示例 JSON 见 `contracts/session-example.json`。

## 4. 状态机与页面对应

```
input ──提交──▶ generating ──成功──▶ ready ──选A/B──▶ reflecting（有回望）
                    │                                 ending    （无回望）
                    │                                    │  ▲ 改选另一个
                    │                                    ▼  │
                    └──失败──▶ error              确认收据 ──▶ complete
```

| `status` | 页面 | 用到的字段 |
| --- | --- | --- |
| （无会话） | 输入页 | — |
| `generating` | 等待 / 摇签页 | `mode`（预置时显示「预置案例演示」） |
| `ready` | 支线页：签题、问签、假设、开场、二选一 | `story.title / question / assumptions / opening / decision / options[].label` |
| `reflecting` | 选项后续 + 回望卡片 | 选中项的 `outcome`、`reflection.goal / concern / alternative` |
| `ending` | 选项后续（无回望）+「整理收据」 | 选中项的 `outcome` |
| `complete` | 收据页（只读）+ 下载 | `receipt.*` |
| `error` | 错误提示 +「重置后重试」/「切换到预置案例」 | `error.message`；`input` 仍在，可用来回填表单 |

选中的选项：`story.options.find(o => o.id === snapshot.selectedOptionId)`。

## 5. 推荐调用流程

### 5.1 页面打开

```ts
const health = await fetch('/api/health').then(r => r.json());
// health.aiConfigured === false → 「看看另一条路」按钮置灰或提示，只能用预置案例
// 之后每 2 秒刷新一次 health，用来更新设备状态角标
```

页面刷新后，前端就丢了旧会话的 id，而后端可能还留着那个会话。所以**页面加载时先调一次 `POST /api/reset`**，这样最省事。

### 5.2 提交

```ts
const requestId = crypto.randomUUID();     // 每次「新提交」生成一次；网络失败重发时复用同一个
const res = await fetch('/api/sessions', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(
    isPreset
      ? { requestId, mode: 'preset', caseId: 'team-project' }        // 预置：不要带 input
      : { requestId, mode: 'live', input: { background, chosenPath, unchosenPath, priority } }
  ),
});
if (res.status !== 202) { /* 读 error.message 显示 */ }
const snap: SessionSnapshot = await res.json();   // status === 'generating'
```

- 点击后**立即禁用按钮**。后端也做了幂等：同一个 `requestId` 重发只建一个会话、只摇一次签。
- 预置模式下，后端会自己填入案例的输入，返回的 `snap.input` 就是案例内容，可以拿来回填表单并锁定。
- 自定义模式下，后端会去掉首尾空格后再保存。

### 5.3 轮询

```ts
const timer = setInterval(async () => {
  const r = await fetch(`/api/sessions/${id}`);
  if (r.status === 404) { stop(); showRestart('服务已重启，请重新开始'); return; }
  const s = await r.json();
  if (s.id !== currentIdRef.current) return;       // 防止旧会话的响应覆盖新会话
  setSnapshot(s);
  if (s.status !== 'generating') stop();
}, 1000);
```

- 预置案例大约 2 秒变成 `ready`；真实 AI 大约 15—20 秒，最长 30 秒（超时后变成 `error` / `AI_TIMEOUT`）。
- reset、组件卸载时都要 `clearInterval`。

### 5.4 选择与改选

```ts
POST /api/sessions/{id}/choice   { "optionId": "A" }
```

- 返回的快照里，`status` 是 `reflecting`（该选项有回望）或 `ending`（没有回望）。**以返回值为准**，不要自己推断。
- 「换一种走法」= 用另一个 optionId 再调一次，**不会重新生成故事**。
- 同一个选项重复提交不会出错，也不会重复触发设备。

### 5.5 确认收据

```ts
// 编辑框初始值取选中项的草稿
const draft = selectedOption.receiptDraft;         // { insight, nextStep }
POST /api/sessions/{id}/receipt   { "insight": "...", "nextStep": "..." }   // 各 1—200 字
```

- 只能在 `reflecting` / `ending` 状态下确认，成功后状态变成 `complete`，返回 `receipt`。
- **确认后不能再修改**（内容不同会返回 409），所以确认成功后要禁用编辑框。
- `receipt.chosenPath / unchosenPath` 来自用户最初的输入，**不是**支线里 A/B 的文案。

### 5.6 下载收据（前端生成 .txt）

```ts
const r = snapshot.receipt!;
const text = [
  '人生支线收据',
  `时间：${new Date(r.createdAt).toLocaleString()}`,
  r.mode === 'preset' ? '（预置案例演示）' : '',
  `现实中的选择：${r.chosenPath}`,
  `未选的道路：${r.unchosenPath}`,
  `这条支线的假设：${r.assumptions.join('；')}`,
  `一次发现：${r.insight}`,
  `现实中的下一步：${r.nextStep}`,
  '',
  '这是基于背景与假设的可能性故事，不代表未来预测。',   // 文档 04 要求前端补这句
].filter(Boolean).join('\n');
const url = URL.createObjectURL(new Blob([text], { type: 'text/plain;charset=utf-8' }));
// <a href={url} download="人生支线收据.txt">
```

### 5.7 重置

```ts
await fetch('/api/reset', { method: 'POST' });
// 成功后：清空表单、快照、requestId、定时器、下载 URL（URL.revokeObjectURL）
```

即使设备离线也会成功；重复调用也没有问题。

## 6. 输入校验（前后端口径一致）

| 字段 | 上限 | 计数方式 |
| --- | --- | --- |
| `background` | 400 | `Array.from(text.trim()).length` |
| `chosenPath` / `unchosenPath` | 100 | 同上 |
| `priority` | 150 | 同上 |
| 收据 `insight` / `nextStep` | 200 | 同上 |

- 四项都必填，去掉首尾空格后不能为空。
- 要用 `Array.from(...)` 计数，**不要用 `.length`**，否则表情符号会被算成 2 个字。
- `contracts/types.ts` 里已经导出了 `INPUT_LIMITS` 和 `RECEIPT_EDIT_LIMIT`。
- 后端校验失败返回 400，`message` 会指出是哪个字段，例如「请填写未选择的道路（最多 100 字）。」

## 7. 错误码处理建议

| HTTP | code | 何时出现 | 前端建议 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 输入为空、超长，或 JSON 格式错误 | 显示 message，保留输入 |
| 400 | `INVALID_OPTION` | optionId 不是 A/B | 不应出现，按程序错误处理 |
| 404 | `SESSION_NOT_FOUND` | 会话已被 reset，或后端重启过 | 提示「服务已重启，请重新开始」，回到输入页 |
| 409 | `SESSION_BUSY` | 已有会话时又提交新请求（包括上一轮 complete/error） | 先 reset 再提交；页面加载时 reset 可以避免 |
| 409 | `REQUEST_CONFLICT` | 同一 requestId 发了不同内容 | 为新内容生成新的 requestId |
| 409 | `REQUEST_EXPIRED` | reset 后又重发旧 requestId | 生成新的 requestId |
| 409 | `INVALID_STATE` | 生成中就去选择、完成后还去选择等 | 以最新快照刷新页面 |
| 409 | `RECEIPT_ALREADY_CONFIRMED` | 确认后改了内容再提交 | 确认后禁用编辑 |
| 503 | `AI_NOT_CONFIGURED` | live 模式但后端没配 AI | 提示用预置案例 |
| 200 快照 `status:error` | `AI_TIMEOUT` / `AI_UNAVAILABLE` / `AI_FORMAT_ERROR` | 生成失败 | 显示 `error.message`，提供「重置后重试」「切换到预置案例」 |

生成失败时，**不要自动切到预置案例**。按文档要求，必须由用户明确点击「切换到预置案例」，并且切换后要标注清楚。

## 8. 设备状态角标（来自 /api/health）

| `device.status` | 显示建议 |
| --- | --- |
| `online` | 寺庙已连接 |
| `offline` | 寺庙未连接（网页流程照常进行） |
| `dryrun` | 模拟设备 |

- `device.lastAck` 为 `accepted` 或 `done` 时，**只表示固件收到了命令**，不代表签筒真的摇了。不要显示「摇签完成」。
- 设备离线**不影响**网页故事流程，不要把网页改成错误状态。
- 前端**不需要**、也不应该直接发任何硬件命令，后端会在状态变化时自动通知设备。

## 9. 联调自测清单

- [ ] 页面打开能显示 health（AI 是否已配置、设备状态）
- [ ] 预置案例：提交 → 等待约 2 秒 → 支线 → 选 A 出现回望 → 换 B → 收据草稿变成 B 的 → 确认 → 下载 .txt
- [ ] 连点提交只产生一个会话（看后端日志只有一次「会话 ... 已创建」和一次 `DRAW`）
- [ ] 刷新页面后能重新开始（不会卡在 SESSION_BUSY）
- [ ] 输入框空着或超长时前端拦截；故意绕过时后端返回的 message 能正常显示
- [ ] 后端关掉再开：页面提示重新开始，不会白屏
- [ ] 真实 AI（在配置好 .env 的电脑上）：等待 15—20 秒后正常出故事；生成失败时出现两个按钮
- [ ] 故事、用户输入都用文本渲染（不要用 `dangerouslySetInnerHTML`）

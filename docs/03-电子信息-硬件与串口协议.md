# 人生支线 电子信息硬件技术文档

负责人：电子信息工程同学。总开发时间八小时。

先读 [项目书第 1—5 节](01-软工A-项目书与前端集成.md)。你负责橡皮泥寺庙模型、签筒摇动、ESP32 固件、TFT 显示、供电和装配。与软工 B 对接 USB 串口；与 UI 同学对接外观和屏幕图。

## 1. 本角色的 MVP

必须有两个真实效果：

1. 橡皮泥捏出寺庙外观，电机或舵机带动轻质签筒摇动。
2. TFT 显示寺庙画面，并随问签、故事、回望和完成切换关键提示。

用户在电脑网页提交，设备接收命令后摇签一次。无须自动掉出真实竹签，不开发传感器输入、触摸操作或语音识别。

## 3. 摇签机械结构

### 3.1 优先方案：SG 舵机摆动轻质签筒

若现有 SG 舵机是常见位置控制舵机，利用小角度往复运动带动纸杯或薄壁塑料签筒。签筒用独立支架承重，舵机通过短连杆带动，不让电机轴直接承受整个模型重量。

橡皮泥负责静态寺庙外观，签筒内用少量短签或轻质模拟签，避免甩出。舵机的中心、摆幅、速度和持续时间由空载、轻载测试确定，在固件中固定上限。

目标：一次 `DRAW` 摇动约 1—2 秒后停止，实际数值以硬件测试为准。固件设置不超过 3 秒的动作上限。不要为了等待 AI 而持续摇签。

### 3.2 普通电机方案

只有在电机类型、驱动器和结构已明确时使用。直流电机可以通过偏心连杆制造摆动，需要电机驱动与相应保护；若是步进电机，使用匹配驱动和已经熟悉的控制方式。

H1.5 前若普通电机结构不稳定，优先换成已验证的 SG 舵机摆动结构。不能把普通电机直接接到 ESP32 GPIO，也不能假定它能够准确转到某个角度。

### 3.3 外壳安排

模型正面展示签筒和 TFT，背面留 USB、电源和检修口。橡皮泥不包覆电路板、散热位置或运动接头。机构先跑通，再装饰；外壳不应挡住观众看到摇动。

## 4. 固件与显示技术

建议使用 Arduino ESP32 环境，继续使用你已经能点亮屏幕的图形库。TFT_eSPI、Adafruit GFX 加匹配驱动等均可，必须与实际屏幕控制芯片匹配。

如果使用位置舵机，采用与当前 ESP32 核心兼容的舵机库或 PWM；普通电机按驱动器接口实现。控制参数留在固件，后端只发业务事件。

### 4.1 TFT 的 P0 实现

使用 UI 提供的 PNG，转换成库支持的 RGB565/C 数组或其他格式。首版采用静态图片与固定中文位图，资源量允许时存内部 Flash；SD 卡不作为启动依赖。

例如一张 240×240 RGB565 原始图约 115200 字节，这只是容量示例，不代表当前屏幕尺寸。不要一次把多张大图全部放到 RAM，按实际 Flash/RAM 与库支持方式存放和绘制。

| 事件 | 屏幕资源 | 机械动作 |
| --- | --- | --- |
| `RESET` | `idle.png`，静候一念 | 立即停止，回到经验证的待机状态 |
| `DRAW` | `draw.png`，正在问签 | 短时摇签一次，然后停止 |
| `STORY` | `story.png`，未选之路 | 不启动电机 |
| `REFLECT` | `reflect.png`，先停一息 | 不启动电机 |
| `RECEIPT` | `receipt.png`，此行已归档 | 不启动电机 |
| `ERROR` | `error.png`，暂未展开 | 停止动作 |

`DRAW` 完成后保留问签画面，直到收到下一个显示事件。若 AI 很快返回 `STORY`，及时更新屏幕，已有短时动作仍按本地截止时间停止；`RESET` 和 `ERROR` 立即中止。

资源转换由硬件负责，UI 负责原图和字号。先转换一张实机检查，再转换其余图片。动态 AI 中文和滚动长段落不属于 P0。

## 5. 串口协议 v1 本文为唯一规范

### 5.1 连接

电脑上的 Java 后端通过 USB 串口连接 ESP32。波特率 `115200`，`8N1`，UTF-8，每行一个 JSON，以 `\n` 结束；接收时容忍 `\r\n`。单行最大 512 字节。

串口只输出协议 JSON。调试信息如需输出，也封装成 `{"type":"log","message":"..."}`，B 忽略 log。缓冲区超过限制时丢弃到下一个换行，并报告错误，不能覆盖内存。

### 5.2 握手与设备重启

电脑打开串口可能导致开发板复位。固件启动先停止执行器，生成本次启动标识 `bootId`，再输出：

```json
{"type":"hello","v":1,"bootId":"b7c20a91","device":"temple-01"}
```

bootId 可用本次启动的随机值转十六进制，不要求永久身份。电脑等待 hello 后才发送命令。板卡收到 `{"type":"ping"}` 时再次输出相同 hello，方便后端重新连接。

### 5.3 命令

```json
{"type":"cmd","v":1,"bootId":"b7c20a91","id":"88e83358-58fb-4c93-94bf-21c323dc4f12","event":"DRAW"}
```

- `id`：Java 后端为每个新事件生成的 UUID 字符串；重发同一事件保留原 id。这样后端单独重启时，不会与板卡仍缓存的命令编号冲突。
- `bootId`：必须与当前启动一致；不一致返回错误，不执行动作。
- `event`：只允许上表六种值。
- 不传电压、转角、速度、时长、用户背景或自由文本。

回执示例：

```jsonl
{"type":"ack","bootId":"b7c20a91","id":"88e83358-58fb-4c93-94bf-21c323dc4f12","status":"accepted"}
{"type":"ack","bootId":"b7c20a91","id":"88e83358-58fb-4c93-94bf-21c323dc4f12","status":"done"}
```

`accepted` 表示固件已接收并安排执行；`done` 表示动作定时结束或画面绘制结束。没有位置传感器，因此 `done` 不证明签筒实际摇动成功，仍需实物观察。

### 5.4 去重、中断与错误

固件保存本次启动最近 16 个命令及状态。相同 id 和相同事件重复到达，返回已有状态，不再次执行。相同 id 却事件不同，返回 `ID_CONFLICT`。本协议不保证跨断电的机械动作“恰好一次”；后端通过禁止重放动作避免重复摇签。

`DRAW` 正在执行时，新的不同 id 的 `DRAW` 返回 `BUSY`。`RESET` 和 `ERROR` 优先中止动作，先把原动作回执标为 `cancelled`，再完成自身命令。显示事件允许更新画面，不取消已有动作的本地停止计时。

```jsonl
{"type":"ack","bootId":"b7c20a91","id":"88e83358-58fb-4c93-94bf-21c323dc4f12","status":"cancelled"}
{"type":"ack","bootId":"b7c20a91","id":"a3612cc2-9ad5-4bf2-b31c-4a4f39c684cf","status":"error","code":"BUSY"}
```

错误代码：`BUSY`、`BAD_COMMAND`、`BOOT_MISMATCH`、`ID_CONFLICT`。无法解析并取得 id 的输入返回 `{"type":"error","code":"BAD_COMMAND"}`，不执行动作。

### 5.5 固件循环

使用基于 `millis()` 的非阻塞动作状态机：读取串口、校验并分派、更新执行器、检查截止时间、处理显示。避免用长时间 `delay()` 阻塞停止命令。

USB 拔掉或后端退出时，已开始的摇动仍必须由本地截止时间停止。上电默认不摇动。不要等待电脑发第二条命令才停止电机。

## 6. 供电与缺件边界

12V 锂电池不直接给常见 SG 舵机、ESP32 低压引脚或不支持该电压的 TFT 供电。核对电池满电电压与降压模块输入范围，按实际规格选择稳压输出和足够的峰值电流。

开发板逻辑与执行器采用适当的供电分支；按接口要求共地。不要同时通过 USB 和外部电源错误回灌开发板。普通电机需匹配的驱动与保护，舵机启动电流不能依靠 GPIO 提供。

第一版优先使用已验证的 USB 逻辑供电和合适的执行器电源；电池移动供电、音频功放和 SD 扩展待闭环完成后再考虑。

缺驱动、降压模块或合适电源时，马上告知全队；不得为赶演示直接接线。只有屏幕可用时可以演示屏幕联动，但摇签 P0 应标注未完成。

## 7. 八小时任务顺序

1. H0—0.5：核对型号、缺件、供电和引脚；交屏幕尺寸。
2. H0.5—1：单独点亮 TFT，空载验证执行器；交串口参数。
3. H1—2：实现 hello、DRAW、RESET 和 ACK；与 B 完成电脑触发实机。
4. H2—4：完成其他显示事件，装轻质签筒与支架，使用 UI 图；最后装静态橡皮泥模型。
5. H4—6：联调完整故事，处理重复命令、复位和供电波动，固定线材。
6. H6—7：连续三轮验收，交接线图、固件、启动与故障说明。
7. H7—8：彩排与复位准备，不再换执行器结构或图形库。

## 8. 交付与验收

交付 `firmware/` 源码、引脚/电源接线表、依赖库版本、烧录步骤和实物照片。接线表写实际验证过的配置，不把未核实型号画成确定接线。

- [ ] 上电不意外摇签。
- [ ] 同一个 DRAW 重发只执行一次。
- [ ] DRAW 本地超时停止；RESET 能中途停止。
- [ ] 三轮带负载摇签无卡死、甩签、板卡重启。
- [ ] 六个状态图实际可显示，中文与颜色正确。
- [ ] hello 和 ACK 能被 Java 后端正确读取。
- [ ] 重连显示当前状态但不重新摇历史签。
- [ ] 模型不遮挡动作、屏幕和检修口。

硬件状态以现场观察为准。把“固件收到命令”“定时动作完成”“实物成功摇动”分开记录。

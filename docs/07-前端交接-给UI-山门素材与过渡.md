# 前端 → UI 交接：山门素材重新导出与视觉确认

前端 → 艺术 UI · 2026-09-26

对象：`temple-entry/temple-entry/`（山门 · 入寺 / 天王殿 · 观心）

前端这次处理了过渡卡顿和鼠标掉帧。剩下的「过渡发糊」主要是素材分辨率不够，代码补不回细节，需要 UI 重新导出。本文说明三件事：

1. 哪些素材要重新导出，按什么规格（第 2、3 节）
2. 前端改了哪些效果，需要你看一眼确认（第 4 节）
3. 怎么交付（第 5 节）

---

## 0. 先看这三条

1. **过渡糊的根本原因是分辨率低。** 入殿视频只有 832×464，在 1920 宽的屏幕上被放大 2.3 倍；它结尾又淡入 1671 宽的殿内图，清晰度会突然跳一下。前端补帧只能让画面变流畅，不能让它变清晰。
2. **视频请按最终速度导出。** 页面现在按 1 倍速播放。原来靠页面把视频放慢（开门 0.65 倍、入殿 0.8 倍），帧率会掉到约 19 帧，这正是卡顿的主要原因。要慢动作，请在导出工具里做好。
3. **首帧、末帧要和前后画面对齐。** 开门视频的首帧和末帧会直接切换成静态图；入殿视频的末帧会淡入殿内图。构图对不上的话，切换时画面会跳。

## 1. 本地查看

双击 `启动预览.cmd`，或在该目录运行 `python serve.py`，浏览器会自动打开。

- 地址后加 `?debug`：显示天王区域、文字锚点、门区域和当前步骤。

建议在 1920×1080 的屏幕上看。高分屏上发糊会更明显。

## 3. 导出规格

### 3.1 图片

- 格式 WebP，质量 85 左右。需要透明背景的导出 RGBA。
- 单张尽量控制在 500 KB 以内（与 `docs/06` 一致）；2560 宽放不下时可放宽，请告诉前端实际大小。
- **替换时不要改构图。** 天王位置、门的位置、门环位置都写死在代码里，构图一变就会错位。如果必须改构图，请在交付时注明，前端会同步修改坐标：
  - 天王、偈文位置：`src/config.js` 中的 `kings`
  - 殿门位置：`src/config.js` 中的 `door`
  - 门环位置：`style.css` 中的 `.knock-left` / `.knock-right`（目前在开门视频画面的 48.44% / 51.56%，66.4% 高度处）

### 3.2 视频

| 项目 | 要求 |
| --- | --- |
| 速度 | **按页面上的最终速度导出**：开门约 4.6 秒，入殿约 2.5 秒。时长想改可以，和前端说一声 |
| 帧率 | 最好直接导出 **60 帧**。工具只能出 24/30 帧也可以，前端来补帧，但画面边缘快速移出的物体可能有轻微残影 |
| 色彩 | 导出时色彩空间选 **Rec.709 / sRGB**，不要留空。未标注色彩的视频，在浏览器里颜色会略有偏差 |
| 音轨 | 不需要，导出时去掉 |
| 入殿视频 | H.264 MP4，yuv420p，1080p 码率 8–10 Mbps |
| 开门视频（透明背景） | **最稳妥的做法是交 PNG 序列（RGBA，带透明通道）**，由前端转码为透明 WebM。如果你能直接导出 VP9 透明 WebM（yuva420p）也可以 |

**衔接要求：**

- 开门视频：首帧等于 `knock-closed.webp`，末帧等于 `knock-open.webp`，逐像素对齐。
- 入殿视频：首帧能接上开门后的山门画面；**末帧的构图要和 `hall.webp` 一致**，因为结尾会淡入它。

> 如果原片是 AI 视频工具生成的，最高只能出 832 宽左右，请告诉前端。前端可以先用 AI 放大（如 Real-ESRGAN）顶上，但效果不如直接高分辨率导出。

## 4. 前端改动：请确认视觉效果

下面这些效果为了流畅改了实现方式。截图对比几乎看不出区别，但请你在真机上看一遍，有不满意的直接提。

| 位置 | 原来 | 现在 | 可能的差别 |
| --- | --- | --- | --- |
| 首页手形光标 | 网页元素跟随鼠标 | **系统原生光标**，阴影直接做进图片 | 跟手、不再掉帧；点击位置移到指尖（原来偏左上约 7px）；靠近窗口右边和下边时，会换成 32px 的小手（浏览器规定，大光标靠边时不能显示） |
| 叩门那一下 | 网页元素 | 不变，只在敲门的 0.7 秒里显示网页元素 | 无 |
| 天王高亮 | 页面实时给整张殿内图调亮，再加遮罩 | 预先生成的四张亮图 `king-*.webp` | 应该一致 |
| 墨字显现、墨迹微晕、偈文化烟 | 实时模糊滤镜 | 每个字叠一层预先模糊的副本，用透明度切换 | 「微晕」更像字边晕开一圈墨，而不是整字变虚 |
| 灯笼光晕、殿门暖光、悬停光 | 「滤色」混合 | 普通叠加 | 色调可能略有不同 |
| 偈文薄雾、墨烟 | 实时模糊滤镜 | 柔边渐变 | 边缘柔和度可能略有不同 |
| 殿内外侧的模糊底图 | 实时模糊 | 预先模糊的小图 `hall-blur.webp` | 应该一致，只有非 16:9 屏幕才看得到 |
| 开门视频、入殿视频 | 原片放慢播放，约 19 帧 | 补帧到 60 帧 | 更流畅；入殿视频右侧，门移出画面的约 0.1 秒里有很淡的门环残影 |

**替换素材后前端要重新生成的东西（UI 只需通知前端）：**

- 换了 `hall.webp`、手形图，或改了天王坐标：前端要重跑 `tools/bake_assets.py`，重新生成天王亮图、光标和模糊底图。
- 换了开门或入殿视频：前端要重新补帧（除非 UI 直接交 60 帧）。

## 5. 交付方式

- 源文件放在 `design/web/temple-entry/`，**文件名沿用现有名称**（例如 `hall.webp`、`enter-hall.mp4`），PNG 序列单独建一个文件夹。
- 交付时附一行说明：尺寸、帧率、时长，以及构图有没有变。
- 前端负责转码、补帧、重新生成配套素材、替换进页面并构建。

### 交付自查

- [ ] 尺寸达到第 2 节的建议值
- [ ] 视频按最终速度导出，色彩空间为 Rec.709，无音轨
- [ ] 开门视频首帧、末帧与两张静态图完全对齐
- [ ] 入殿视频末帧与 `hall.webp` 构图一致
- [ ] 构图有变化时写明了新坐标，或注明「构图未变」
- [ ] 在本地预览里看过第 4 节的效果，有意见已反馈

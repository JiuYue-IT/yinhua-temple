# 人生支线 艺术 UI 技术交付文档

负责人：艺术 UI 同学。开发总时长八小时。

先读 [项目书第 1—5 节](01-软工A-项目书与前端集成.md)。本角色负责视觉与交互设计、网页素材、TFT 素材，以及橡皮泥模型的外观建议；前端代码由软工 A 实现，电路和模型机械装配由硬件同学负责。

## 1. 你需要交付什么

不是做完整品牌手册。交付能够立即被开发同学使用的页面与素材，并在真实网页和小屏上检查效果。

| 交付物 | 内容 | 截止 | 接收人 |
| --- | --- | --- | --- |
| 低保真流程 | 输入、等待、支线、回望、收据五种视图 | H1 | A |
| 视觉规范 | 色值、字体、字号、按钮和间距 | H1 | A |
| 首批网页素材 | 寺庙主图、灯火或签筒元素、收据底纹 | H2 | A |
| TFT 首批图 | 按硬件确认尺寸制作寺庙待机图 | H2 | 硬件 |
| 全部状态图/短句 | 问签、支线、回望、归来、错误 | H3 | 硬件 |
| 页面与实物修正 | 检查文字可读性、遮挡、颜色和模型外观 | H4—6 | A 与硬件 |
| 演示画面检查 | 检查投屏和观众观看距离 | H6—7 | 全队 |

H1 先交结构和规范，不要等所有插画画完。开发可以先用色块占位，再替换素材。

## 2. 推荐风格与表达

方向：小型寺庙、纸签、暖色灯火、少量电子光效。让“现实选择”和“未选支线”在视觉上可区分，同时保持同一个空间。

建议起始色板，可在 H1 前调整：背景 `#151821`，纸签 `#F5EDD9`，主文字 `#F4F0E6`，暖金 `#D8B36A`，支线青 `#80BDB3`，辅助文字 `#B8BAC3`。正文与背景须保持清晰对比。

网页正文使用设备可用的中文无衬线字体，避免额外下载大字体包。装饰性书法字仅用于少量标题，可转为图形。主要按钮和长故事文字不能使用难以辨认的装饰字体。

回望用暂停、留白和温和高亮表达，不用“判错”的红色警报或打分。随机签文也不画成吉凶保证。

## 3. 五种视图怎么设计

### 3.1 输入

必须有四项：背景、已选道路、未选道路、在意的目标。背景限制 400 字符，两个道路各 100，目标 150。

主按钮“看看另一条路”，旁边提供“载入演示案例”。演示案例是独立模式，显示明确标识，不让用户以为预置故事来自其自定义资料。

顶部保留一行说明：“根据你的背景探索一种可能，不代表未来预测。”底部留小型设备状态位置，状态文字由程序提供。

### 3.2 等待与摇签

展示寺庙和“正在展开未选之路”。不设计伪进度百分比，也不要求前端精准预测 AI 等待时间。

可以做简单 CSS 灯火呼吸效果。设备摇签只持续一小段，等待 AI 时画面继续等待，不能暗示电机需要一直转。

### 3.3 支线

从上到下：签题、反思问题、背景假设、开场情节、一个二选一节点。要标注“你在支线中遇到了新的选择”，避免用户误以为改写了原来真实决定。

正文使用卡片或段落，不能把整个故事做成图片。两种选项视觉上平等，不提前用绿色和红色给选项定性。

### 3.4 回望与后续

选项后续与回望可以在同页展示。回望卡片固定三个标签：

- 你原本想要。
- 这一步可能带来。
- 还有一种走法。

按钮：“换一种走法”“保留当前走向并整理收据”。没有回望的普通后续也要有“整理收据”。

### 3.5 收据

采用纸质小票的视觉。固定字段：真实选择、未选道路、一次发现、现实中的下一步、可能性说明。

“一次发现”和“下一步”是可编辑文本。主按钮“确认收据”，确认后“下载收据”。本次下载格式为 `.txt`，不要设计必须依赖打印机或高清海报导出的流程。

## 4. 网页资产交付技术

使用自己熟悉的 Figma、Photoshop、Illustrator 或其他工具，不要求临时更换。交付到 `design/web/`：

| 文件 | 推荐格式 | 用途 |
| --- | --- | --- |
| `temple-hero.svg` 或 `.png` | SVG 或透明 PNG | 输入页/等待页寺庙图 |
| `receipt-texture.png` | 小尺寸 PNG | 可选的收据底纹 |
| `tokens.md` | 文本 | 色值、字号、间距、按钮圆角 |
| `screens-overview.png` | PNG | 页面布局总览，供 A 实现 |

屏幕参考尺寸以现场电脑为准，优先提供 1366×768 桌面布局，正文区可滚动。手机完整适配不是 P0。

图形资产不嵌入长段正文。设计稿写清按钮状态：正常、悬停、禁用、加载；错误信息有独立位置。简单图标优先 SVG，复杂插画 PNG，单张网页图尽量控制在 500KB 内，避免大视频背景。

## 5. TFT 屏幕资源对接

### 5.1 先拿规格再绘图

硬件同学必须在 H0.5 前提供：有效宽高、横竖方向、可见区域、控制芯片、使用的图形库与支持的图片格式。不得默认屏幕是 240×240，也不得默认支持触摸。

你交 PNG 源图；硬件同学负责转为 RGB565、C 数组或图形库支持的格式，检查字节序和颜色。不要把硬件图片转换任务转给前端。

### 5.2 P0 屏幕内容

屏幕允许只显示寺庙画面和固定关键短句，这已经满足“重要对话或寺庙画面”的 MVP 要求。动态 AI 长句留在网页，避免八小时内临时实现完整中文字库。

| 协议事件 | 画面建议 | 固定短句 |
| --- | --- | --- |
| `RESET` | 寺庙待机 | 静候一念 |
| `DRAW` | 签筒/灯火 | 正在问签 |
| `STORY` | 一条向远处延伸的小路 | 未选之路 |
| `REFLECT` | 静止灯火 | 先停一息 |
| `RECEIPT` | 归来的灯/纸签 | 此行已归档 |
| `ERROR` | 平静的等待画面 | 暂未展开 |

PNG 名称依次为 `idle.png`、`draw.png`、`story.png`、`reflect.png`、`receipt.png`、`error.png`，放在 `design/tft/`。

固定中文字可以直接画进状态图片，设备不接收用户私人文本。若内存不足，由硬件同学使用寺庙基础图配少量文字位图，减少完整画面数量；状态语义保持不变。

中文首版建议每行四到八字，使用粗而清晰的字形。小屏不放大段对白、复杂细线或低对比背景。

## 6. 橡皮泥模型怎么参与

提供一个简单正视图和配色即可：固定的寺庙外观、前方可见签筒、清晰的 TFT 窗口。为 USB、电源和复位预留开口。

橡皮泥用于静态外壳装饰。重的泥塑不装到电机轴上，不包住发热器件，不盖住检修位置。签筒和运动支架由硬件同学确认尺寸与负载。

不要为外观牺牲可观看性：观众需要看得见签筒真的摇动，也看得清屏幕变化。

## 7. 完成标准与协作边界

- A 能在不反复询问的情况下拿到色值、布局、文件名和按钮文案。
- 硬件拿到正确尺寸的状态 PNG，首张转换后现场检查颜色与中文。
- H4 前在真实浏览器检查一遍，H6 前在真实 TFT 检查一遍，不能只看设计软件。
- 收据编辑、等待、失败、设备离线都有可用布局。
- H6 后只改阻碍阅读和演示的问题，不重做整套风格。

交付完成时注明：哪些网页已经实际实现、哪些仍是设计稿；哪些 TFT 图已实机显示。不要把效果图当成实际硬件照片。

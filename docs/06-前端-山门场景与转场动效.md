# 人生支线 山门场景与转场动效 技术文档

给软工 A（前端）。本文说明寺庙山门场景的实现方式：素材怎么来、图层怎么叠、每个动画怎么做、为什么这样做不卡，以及怎么搬进 React 项目。

可运行的参考实现在 `design/web/demo/index.html`，双击即可打开，不依赖任何构建工具。本文所有代码片段都来自这个文件，集成时以它为准。

---

## 0. 一分钟看懂

- **不用 Three.js、不用 Canvas、不加任何依赖。** 只用普通 HTML、CSS 和几十行原生 JS，符合项目书"React + Vite + TypeScript + 普通 CSS"的约定。
- **画面是图片，不是 CSS 画出来的。** 插画拆成两张图叠起来：前景（门框、天王、灯笼，门洞挖空）和背景（门洞后面的整座庭院）。
- **所有动效只改 `transform` 和 `opacity`。** 这是不卡的关键，第 6 节专门讲。
- **核心转场叫"穿过山门"**：前景以门洞中心为轴放大并淡出，背景只轻微放大，看起来像镜头穿门走向大殿。
- **文字全部是 HTML**，叠在图上，不画进图片里。

演示操作：

| 操作 | 效果 |
|---|---|
| 移动鼠标 | 两层以不同幅度平移（视差） |
| 点"推开山门"或按回车 | 穿门转场，约 2.4 秒后支线卡片浮出（模拟 AI 返回） |
| 点"回到山门"或按 Esc | 反向转场，回到门口 |
| 按 D | 前景半透明，检查两层是否对齐 |
| 地址后加 `#inner` | 打开后直接进入内页，方便调试 |

## 2. 素材生产流程

整个流程不需要 PS，美术只需要做一次 GPT 扩图。

```
source.png ──make_layers.py──┬──> gate-fg.webp   （前景，门洞挖空）
                             ├──> gpt-input.png  （门洞内容 + 四周白色）
                             │         │
                             │         └──GPT 扩图──> gpt-bg.png
                             │                            │
                             └──make_layers.py（再跑一次）─┴──> temple-bg.jpg（背景）
                                                               grain.png（颗粒）
```

### 2.1 运行脚本

```bash
cd design/web/demo
pip install pillow numpy
python make_layers.py
```

脚本是幂等的，随时可以重跑。目录里有 `gpt-bg.png` 时会自动合成正式背景；没有时生成一张"门洞内容 + 边缘拉伸模糊"的占位背景，页面照样能跑。

### 2.2 前景：怎么挖掉门洞

门洞不是规则矩形（上沿有斗拱齿、中间挂着灯笼），所以用"颜色 + 泛洪填充"自动算出门洞形状：

1. **找出门框。** 朱红色像素（`R>150 且 R-G>50 且 R-B>70`）就是门框。再加上一个包围框 `BOX`，框外全部当作墙，门洞只可能在框内。
2. **封住灯笼。** 中间那盏灯笼的挂绳挡在门楣前面，如果不封住，填充会顺着挂绳缝隙漏出去，把整个门框都挖掉。所以先把灯笼区域 `LANTERN` 整块当作墙。
3. **从门洞里的石板路开始泛洪。** 门框先膨胀 2 像素，堵住纹理里的细缝，然后从种子点 `(835, 740)` 向外填充，填到的区域就是门洞。
   - 种子点必须落在门洞内、而且不是橙色的地方。一开始放在 `(835, 500)`，正好落在大殿屋顶的橙色法轮上，填充直接失败。
4. **补洞。** 门洞内部被包住的橙色区域（大殿墙面、法轮）也要算进门洞，这些是背景的一部分。
5. **还原边缘。** 把第 3 步膨胀吃掉的边缘还回来，但不越过橙色门框。
6. **灯笼内部。** 灯笼框里只挖掉天空色像素，灯笼本身保留在前景。
7. **羽化。** 透明通道做 0.7 像素高斯模糊，避免锯齿，然后导出 WebP。

> 踩过的坑：Pillow 12 里 `Image.fromarray()` 生成的图片直接调用 `ImageDraw.floodfill` 不生效，也不报错。必须先 `.copy()` 一次。脚本里的 `img()` 辅助函数就是为此写的。

### 2.3 背景：GPT 扩图

前景挖空后，门洞后面只有原图那一小块画面。视差平移和穿门放大时，门框会移开，露出原本被门框挡住的区域，所以背景必须比门洞大，需要 GPT 把四周补齐。

**输入图 `gpt-input.png`**：门洞内容放在和原图完全相同的位置，四周是白色。门洞内容的上沿裁掉了 32 像素（夹着斗拱齿）、左右各 6 像素（柱子碎片），灯笼位置用同一行最近的门洞像素补上，保证交给 GPT 的是一块干净画面。

**提示词：**

> 这是一张横版插画的局部，画面中间是一座日式寺庙大殿，四周白色区域是空白。请把画面向四周扩展，补满整张图片，输出 16:9 横版。
>
> 要求：
> 1. 中间已有的画面（大殿、樱花、石灯笼、远山、石板路）保持原样，位置和大小都不要改动，不要重画。
> 2. 扩展部分延续原画风格：扁平复古插画，带颗粒纸张质感，配色是柔和的天蓝、墨绿、樱粉、朱红和米白，光线是明亮的春日白天。
> 3. 上方：延续蓝天和白云。
> 4. 左右两侧：延续樱花树、松树、灌木和石灯笼，保持对称构图。
> 5. 下方：石板路继续延伸向观众，两侧是草地。
> 6. 画面里不要出现门框、柱子、建筑框架、人物或文字，要看起来像一幅站在庭院里完整看到的风景。

**怎么挑结果。** GPT 这次出了两张，我把每张图的大殿区域和原图做了逐像素比对：

| | 与原图的平均色差 | 位置偏移 | 结论 |
|---|---|---|---|
| 第一张 | 51.5 | 左 10、上 30 像素，且被放大 | 不用，和前景对不上 |
| 第二张 | 8.8 | 0 | 采用 |

没有脚本时也可以肉眼检查：把扩图结果放成 `gpt-bg.png`，跑脚本，打开页面按 D，看大殿边缘有没有重影。

**合成。** 即使 GPT 没有移位，它也会轻微重画中间部分。所以脚本会把原图门洞内容贴回中间，边缘向内收 10 像素左右、做 8 像素羽化。接缝落在门框背后，看不到。最终导出为渐进式 JPEG，质量 86。

### 2.4 纸张颗粒

原图本身有颗粒质感，但门框放大 2.8 倍后颗粒会被放大变糊。所以额外叠一层固定大小的颗粒，放大过程中质感保持一致。

`grain.png` 由脚本生成：256×256 的随机噪点，深棕色，透明度代表颗粒强度。页面里平铺，整体 `opacity: .22`。

> 不要用 SVG 的 `feTurbulence` 实时生成噪点。第一版就是这么做的，放大时它每帧都要重算，是卡顿的主要原因之一。

### 2.5 美术改图后怎么更新

- **只改了颜色、细节，构图不变**：替换 `source.png`，重跑脚本即可。GPT 扩图结果可以继续用。
- **构图变了（门洞位置或大小变了）**：需要改脚本顶部的 `BOX`、`LANTERN` 和泛洪种子点，重跑得到新的 `gpt-input.png`，重新做一次 GPT 扩图，最后同步更新第 3.2 节里的百分比坐标。

## 3. 场景结构

### 3.1 DOM 层级（从下到上）

```html
<div class="stage">                     <!-- 场景容器，按原图比例铺满视口 -->
  <div class="layer bg">                <!-- 背景层：远，移动少 -->
    <img src="temple-bg.jpg">
    <div class="sun-wrap"><div class="sun"></div></div>   <!-- 门洞里的斜向阳光 -->
    <div class="petals back"></div>                       <!-- 远处樱花 -->
  </div>

  <div class="layer fg">                <!-- 前景层：近，移动多，转场时放大淡出 -->
    <img src="gate-fg.webp">
    <div class="glow l"></div>          <!-- 三盏灯笼的光晕 -->
    <div class="glow r"></div>
    <div class="glow c"></div>
    <div class="dapple-wrap"><div class="dapple"></div></div>  <!-- 地面光斑 -->
  </div>

  <div class="petals front"></div>      <!-- 近处樱花，在所有图层之上 -->
</div>

<div class="grain"></div>               <!-- 纸张颗粒，固定在视口，不跟着缩放 -->
<div class="shade vignette"></div>      <!-- 暗角 -->
<div class="shade dim"></div>           <!-- 内页压暗，给卡片文字做对比 -->

<div class="ui">...</div>               <!-- 所有文字和按钮 -->
```

**为什么光晕和光斑放在前景层里？** 它们是贴在门框、灯笼、地面上的效果，必须跟着前景一起平移、放大、淡出，否则转场时会悬在半空。同理，阳光和远处樱花放在背景层里。

**为什么颗粒和遮罩放在 `.stage` 外面？** 它们要固定在屏幕上，不跟着图层缩放。而且放在外面，它们就不会被卷进缩放图层的重绘里。

### 3.2 坐标系统

所有元素的位置都用**相对原图 1671×941 的百分比**表示。这样不管屏幕多大，光晕都能准确落在灯笼上。

| 位置 | 原图像素 | 百分比 | 用途 |
|---|---|---|---|
| 门洞中心 | (836, 543) | 50.03%, 57.7% | 缩放轴心 `--door-x` / `--door-y` |
| 左灯笼 | (475, 145) | 28.43%, 15.4% | `.glow.l` |
| 右灯笼 | (1201, 145) | 71.87%, 15.4% | `.glow.r` |
| 中灯笼 | (834, 305) | 49.9%, 32.4% | `.glow.c` |
| 门洞范围 | x 500–1172，y 304–782 | 29.9%–70.1%，32.3%–83.1% | 阳光区域 |

门洞中心是 `(500+1172)/2` 和 `(304+782)/2`。要在图上加新的装饰时，先在原图里量出像素坐标，再除以 1671 和 941。

### 3.3 铺满视口

```css
.stage {
  position: absolute;
  left: 50%; top: 50%;
  width: max(100vw, calc(100vh * 1671 / 941));
  aspect-ratio: 1671 / 941;
  translate: -50% -50%;
}
.layer { position: absolute; inset: 0; }
.layer > img { width: 100%; height: 100%; display: block; }
```

效果等同于 `object-fit: cover`：保持比例，铺满屏幕，多余部分从两边或上下裁掉，居中对齐。

不能直接给每张 `<img>` 写 `object-fit: cover`，因为光晕等元素是按百分比定位在容器上的。只有让整个容器保持原图比例，百分比坐标才和图片对得上。

1366×768 的屏幕比例是 1.779，原图是 1.776，几乎不会裁切。

## 4. 各个动效的实现

### 4.1 鼠标视差

前景平移幅度大，背景小，产生纵深感。

```js
const bgEl = document.querySelector('.bg'), fgEl = document.querySelector('.fg');
let tx = 0, ty = 0, cx = 0, cy = 0, running = false;

function tick() {
  cx += (tx - cx) * 0.08;               // 每帧向目标靠近 8%，产生缓动跟随
  cy += (ty - cy) * 0.08;
  bgEl.style.translate = `${(cx * -12).toFixed(2)}px ${(cy * -6).toFixed(2)}px`;
  fgEl.style.translate = `${(cx * -34).toFixed(2)}px ${(cy * -14).toFixed(2)}px`;
  running = Math.abs(tx - cx) + Math.abs(ty - cy) > 0.0005;
  if (running) requestAnimationFrame(tick);   // 追上目标后停止，不空转
}

addEventListener('pointermove', e => {
  tx = e.clientX / innerWidth - 0.5;    // -0.5 ~ 0.5
  ty = e.clientY / innerHeight - 0.5;
  if (!running) { running = true; requestAnimationFrame(tick); }
});
```

要点：

- **幅度**：背景 ±6 px，前景 ±17 px（系数的一半）。鼠标向右时画面向左移，方向是负号。想加强纵深就加大两者的差距，但背景层四周要有余量，第 3.3 节的 `scale: 1.06` 就是给平移留的边。
- **缓动**：不直接跟随鼠标，而是每帧追 8%，手感更柔和。
- **不空转**：鼠标停下、画面追上后停止 `requestAnimationFrame` 循环。第一版一直在跑，鼠标不动也每帧写样式。
- **直接写元素的 `style.translate`**，不要写到 `:root` 的 CSS 变量上。改根元素上的变量，浏览器要把整棵树的样式重新算一遍。

#### 关键技巧：`translate` 和 `scale` 是两个独立属性

注意代码里用的是 `translate` 和 `scale` 两个 CSS 属性，而不是 `transform: translate(...) scale(...)`。

视差由 JS 每帧改 `translate`，转场由 CSS 过渡改 `scale`。如果两者都写在 `transform` 里，JS 一写就会把 CSS 的缩放过渡覆盖掉，反之亦然。拆成两个独立属性后，两者互不干扰，而且都走 GPU 合成。

浏览器支持：Chrome 104、Safari 14.1、Firefox 72 起支持。现场演示电脑的浏览器都没问题。

### 4.2 穿门转场

用 `<body data-view="...">` 表示当前状态，CSS 根据状态切换目标值，由 `transition` 负责动画。

```css
.fg, .bg { transform-origin: var(--door-x) var(--door-y); }   /* 以门洞中心为轴 */

/* 门口（默认） */
.fg { scale: 1.03; transition: scale 1.8s cubic-bezier(.65, 0, .25, 1), opacity .6s ease; }
.bg { scale: 1.06; transition: scale 1.8s cubic-bezier(.65, 0, .25, 1); }

/* 穿门中 / 已在门内 */
body[data-view="passing"] .fg,
body[data-view="inner"]   .fg {
  scale: 2.8; opacity: 0;
  transition: scale 1.8s cubic-bezier(.65, 0, .25, 1), opacity .8s ease .7s;
}
body[data-view="passing"] .bg,
body[data-view="inner"]   .bg { scale: 1.3; }
body[data-view="inner"] .shade.dim { opacity: 1; }
```

时间线（进门）：

```
0s     点击，门口牌匾淡出
0s     前景开始放大 1.03 → 2.8，背景 1.06 → 1.3（1.8s，先慢后快再慢）
0.7s   前景开始淡出（0.8s）
1.5s   切换到 inner，底部压暗，内页 UI 淡入
1.8s   缩放结束
—      AI 返回后，支线卡片上浮淡入（0.7s）
```

设计说明：

- **两层放大倍数不同**（2.8 对 1.3）是纵深感的来源。前景近，放大得多；背景远，放大得少。
- **缓动曲线** `cubic-bezier(.65, 0, .25, 1)` 起步慢、中段快、收尾慢，像镜头推进的节奏。
- **前景延迟 0.7 秒才淡出**：先让观众看清"门框在变大"，再消失，否则会像普通淡入淡出。
- **最初前景放大到 3.6 倍**，后来改成 2.8。放大倍数越大，GPU 要处理的纹理越大，2.8 倍视觉上已经完全穿过门框。
- **返回**时是同一套过渡反向播放。门框从 2.8 缩回 1.03、重新淡入，1.1 秒后显示牌匾。

### 4.3 灯火呼吸

在每盏灯笼的位置叠一个暖黄色径向渐变圆，循环改变透明度和大小。

```css
.glow {
  position: absolute;
  width: 13%; aspect-ratio: 1;
  translate: -50% -50%;              /* 以灯笼中心定位 */
  border-radius: 50%;
  background: radial-gradient(circle,
    rgba(255, 222, 160, .5) 0%,
    rgba(255, 196, 120, .16) 32%,
    transparent 64%);
  animation: breathe 3.4s ease-in-out infinite alternate;
  will-change: transform, opacity;
}
.glow.r { animation-delay: -1.3s; }   /* 三盏错开，不同步闪烁 */
.glow.c { width: 9%; animation-delay: -2.2s; }

@keyframes breathe {
  0%   { opacity: .45; scale: .94; }
  55%  { opacity: .9;  scale: 1.03; }
  62%  { opacity: .72; }              /* 一次轻微的回落，像火苗晃了一下 */
  100% { opacity: .95; scale: 1.06; }
}
```

- 负数的 `animation-delay` 表示"从动画中间开始播"，三盏灯一打开就处在不同阶段。
- 等待页的小灯 `.lamp` 复用同一个 `breathe` 动画，节奏更快（1.6s）。
- 第一版用了 `mix-blend-mode: screen`（滤色混合）让光更通透，但混合模式会迫使浏览器每帧重算下面整张门框图，已去掉。普通半透明叠加在这种暖色画面上看不出区别。

### 4.4 门洞里的斜向阳光

一条斜向的半透明亮带，在门洞区域里左右缓慢扫过。

```css
.sun-wrap {                           /* 门洞范围，裁掉超出部分 */
  position: absolute; left: 29%; top: 31%; width: 42%; height: 53%;
  overflow: hidden;
}
.sun {
  position: absolute; top: 0; bottom: 0; left: -50%; width: 60%;
  background: linear-gradient(112deg,
    transparent 20%, rgba(255, 248, 228, .22) 50%, transparent 80%);
  animation: sun 14s ease-in-out infinite alternate;
}
@keyframes sun { from { transform: translateX(0); } to { transform: translateX(150%); } }
```

做法是"外层固定裁切，内层整体平移"。第一版是动画 `background-position`，那样每帧都要重绘，现在是纯位移。

### 4.5 地面光斑

模拟树影在地面上摇动，思路和阳光相同。

```css
.dapple-wrap { position: absolute; left: 0; right: 0; top: 80%; bottom: 0; overflow: hidden; }
.dapple {
  position: absolute; inset: 0 -20% 0 -5%;   /* 比容器宽，平移时不露边 */
  background:
    radial-gradient(ellipse 4% 24% at 20% 40%, rgba(255, 250, 235, .28), transparent 70%),
    radial-gradient(ellipse 6% 30% at 55% 70%, rgba(255, 250, 235, .24), transparent 70%),
    radial-gradient(ellipse 3% 20% at 80% 30%, rgba(255, 250, 235, .28), transparent 70%),
    radial-gradient(ellipse 5% 26% at 38% 15%, rgba(255, 250, 235, .22), transparent 70%);
  background-size: 50% 100%;                 /* 4 个光斑重复平铺 */
  animation: dapple 18s ease-in-out infinite alternate;
}
@keyframes dapple { from { transform: translate(0, 0); } to { transform: translate(8%, 4%); } }
```

光斑放在前景层里，只覆盖画面下方 20%（近处地面），穿门时随前景一起淡出。

### 4.6 樱花飘落

每片花瓣是两层 `div`：外层负责下落和旋转，内层负责翻转。两个动画周期不同，叠加起来就显得随机。

```css
.petal {
  position: absolute; top: 0;
  width: var(--s); height: calc(var(--s) * .72);
  animation: fall var(--t) linear var(--d) infinite;
}
.petal i {
  display: block; width: 100%; height: 100%;
  background: linear-gradient(135deg, #ffe4ec, #f5b3c6);
  border-radius: 100% 0 100% 0;          /* 对角两个圆角 = 花瓣形状 */
  animation: flutter calc(var(--t) / 4) ease-in-out infinite alternate;
}
@keyframes fall {
  from { transform: translate3d(0, var(--y0), 0) rotate(0deg); opacity: 0; }
  8%   { opacity: 1; }
  90%  { opacity: 1; }
  to   { transform: translate3d(var(--dx), var(--y1), 0) rotate(var(--rot)); opacity: 0; }
}
@keyframes flutter {
  from { transform: rotate3d(1, .4, 0, 0deg); }
  to   { transform: rotate3d(1, .4, 0, 70deg); }   /* 绕斜轴翻转，像花瓣在翻面 */
}
```

每片花瓣的参数由 JS 随机生成，写进 CSS 变量：

```js
function spawn(el, n, o) {
  for (let i = 0; i < n; i++) {
    const p = document.createElement('div');
    p.className = 'petal';
    const r = (a, b) => a + Math.random() * (b - a);
    p.style.cssText =
      `left:${r(o.x0, o.x1)}%;` +      // 水平起点
      `--s:${r(o.s0, o.s1)}px;` +       // 大小
      `--t:${r(o.t0, o.t1)}s;` +        // 下落时长
      `--d:${-r(0, o.t1)}s;` +          // 负延迟：一打开就满屏都有花瓣
      `--y0:${o.y0};--y1:${o.y1};` +    // 起止高度
      `--dx:${r(-8, 14)}vw;` +          // 水平漂移（偏右，像有风）
      `--rot:${r(180, 540)}deg`;        // 总旋转角度
    p.innerHTML = '<i></i>';
    el.appendChild(p);
  }
}
// 远处：在门洞范围内，小而慢，属于背景层
spawn(petalsBack, 22, { x0: 30, x1: 66, s0: 5, s1: 9, t0: 9, t1: 15, y0: '30vh', y1: '80vh' });
// 近处：少量、大、半透明，覆盖全屏，在所有图层之上
spawn(petalsFront, 7, { x0: 0, x1: 90, s0: 16, s1: 24, t0: 7, t1: 11, y0: '-10vh', y1: '110vh' });
```

- 远近两组花瓣大小、速度不同，也是纵深感的一部分。
- 近处花瓣第一版用了 `filter: blur()` 做景深模糊，每片都要单独计算模糊，已改成 `opacity: .8`。
- 总共 29 片，CSS 动画开销很小。想要几百片再考虑换 Canvas。

### 4.7 遮罩与界面切换

**两块遮罩，只切换透明度：**

```css
.shade { position: fixed; inset: 0; pointer-events: none; transition: opacity 1.2s ease; }
.shade.vignette { background: radial-gradient(ellipse at 50% 55%, transparent 55%, rgba(21, 24, 33, .35)); }
.shade.dim { background: linear-gradient(to top, rgba(21, 24, 33, .8), rgba(21, 24, 33, .2) 60%, rgba(21, 24, 33, .06)); opacity: 0; }
body[data-view="inner"] .shade.dim { opacity: 1; }
```

第一版是直接对 `background` 做过渡，渐变之间的过渡浏览器做不了平滑动画，而且每帧都要重绘。现在两种遮罩各占一层，只改透明度。

**界面视图淡入淡出：**

```css
.ui   { position: fixed; inset: 0; display: grid; place-items: end center; }
.view { grid-area: 1 / 1; transition: opacity .6s ease, translate .8s cubic-bezier(.2, .7, .2, 1); }
.view[hidden] { display: block; opacity: 0; translate: 0 24px; pointer-events: none; }
```

- 所有视图放在同一个网格格子里重叠，切换时不会跳动。
- 浏览器默认 `hidden` 是 `display: none`，那样就没有过渡了。这里改成 `display: block` 加透明，保留淡出动画，同时 `pointer-events: none` 让隐藏的按钮点不到。
- 支线卡片用 `.card.show` 控制上浮淡入，时间点由数据决定（AI 返回时加上 `show`）。

**卡片背景**：第一版用了 `backdrop-filter: blur()` 毛玻璃，但卡片后面有樱花在动，每帧都要重算模糊，改成了 84% 不透明的深色底。

### 4.8 减少动态效果

系统开启"减少动态效果"时（Windows：设置 → 辅助功能 → 视觉效果 → 动画效果），关闭所有循环动画、樱花和视差，转场只保留淡入淡出，不做缩放：

```css
@media (prefers-reduced-motion: reduce) {
  .glow, .sun, .dapple, .petal, .petal i, .lamp { animation: none !important; }
  .petals { display: none; }
  .bg, .fg { translate: none !important; transition: opacity .6s !important; }
  body[data-view="inner"] .fg, body[data-view="passing"] .fg { scale: 1.03; }
  body[data-view="inner"] .bg, body[data-view="passing"] .bg { scale: 1.06; }
}
```

JS 里对应判断 `matchMedia('(prefers-reduced-motion: reduce)').matches`，不生成花瓣、不绑定视差，转场等待时间从 1500 ms 缩短到 300 ms。

**现场演示前请确认演示电脑没有开这个选项**，否则会以为动画坏了。

## 5. 转场状态机

```
        enter()                  1.5s 后
gate ───────────> passing ───────────────> inner
  ^                                          │
  └───────────────── back() ─────────────────┘
          （1.1s 后重新显示牌匾）
```

| 状态 | 前景 | 背景 | 界面 |
|---|---|---|---|
| `gate` | 1.03 倍，不透明 | 1.06 倍 | 牌匾 |
| `passing` | 放大到 2.8 倍，淡出 | 放大到 1.3 倍 | 全部隐藏 |
| `inner` | 同上（保持） | 同上（保持） | 等待提示 → 卡片；底部压暗 |

```js
const ready = Promise.all(
  [...document.querySelectorAll('.stage img')].map(i => i.decode().catch(() => {}))
);

async function enter() {
  if (body.dataset.view !== 'gate') return;   // 防止重复触发
  await ready;                                 // 图片解码完才开始，见第 6.2 节
  timers.forEach(clearTimeout); timers = [];
  body.dataset.view = 'passing';
  vGate.hidden = true;
  later(() => { body.dataset.view = 'inner'; vInner.hidden = false; }, 1500);
}

function back() {
  if (body.dataset.view === 'gate') return;
  timers.forEach(clearTimeout); timers = [];   // 打断进行中的进门流程
  vInner.hidden = true;
  body.dataset.view = 'gate';
  later(() => { vGate.hidden = false; }, 1100);
}
```

- 所有定时器统一存在 `timers` 里，每次切换前清空。这样转场进行到一半按 Esc，也不会在返回后又突然跳到内页。
- demo 里用 2.4 秒定时器模拟 AI 返回，正式版要换成接口数据驱动，见第 7.3 节。

## 6. 性能：为什么第一版卡，现在为什么不卡

### 6.1 实测数据

测试方法：用 Puppeteer 驱动 Chrome，1366×768、1.5 倍缩放，点击"推开山门"后用 `requestAnimationFrame` 记录 2 秒内每一帧的间隔。

| | 2 秒内帧数 | 平均每帧 | 最长一帧 |
|---|---|---|---|
| 第一版 | 13 帧 | 176 ms | **1219 ms** |
| 现在 | 约 440 帧 | 4.6 ms | 约 40 ms（仅 1 帧） |

1.2 秒那一帧，就是"一点击就卡住，然后画面直接跳到结尾"。

### 6.2 原因和修复

浏览器渲染一帧分三步：**布局**（算位置大小）→ **绘制**（把像素画出来）→ **合成**（把画好的图层叠起来）。

只改 `transform` 和 `opacity` 时，浏览器只做"合成"这一步，由 GPU 完成，非常快。其他属性一变，就要重新"绘制"。对一张放大了 2.8 倍、铺满全屏的图层逐帧重绘，一定会卡。

| 第一版的写法 | 问题 | 现在的写法 |
|---|---|---|
| 颗粒用 SVG `feTurbulence` 实时生成，放在缩放层里 | 放大时每帧重新生成整屏噪点 | 预渲染 `grain.png` 平铺，放在缩放层外 |
| 光晕、光斑用 `mix-blend-mode` | 混合模式要读取下层像素，每帧重算整张门框 | 普通半透明叠加 |
| 阳光、光斑动画 `background-position` | 每帧重绘 | 外层裁切、内层 `transform` 平移 |
| 近处花瓣 `filter: blur()` | 每片每帧重算模糊 | `opacity` 半透明 |
| 卡片 `backdrop-filter: blur()` | 背后花瓣在动，每帧重算毛玻璃 | 不透明深色底 |
| 遮罩对 `background` 渐变做过渡 | 无法平滑插值，每帧重绘 | 两层遮罩，只切 `opacity` |
| 内页用 `filter: saturate() brightness()` 压暗背景 | 对整张背景图逐帧调色 | 用 `.shade.dim` 遮罩代替 |
| 视差写 `:root` 上的 CSS 变量，且永不停止 | 每帧整树重算样式 | 直接写两个元素的 `style.translate`，追上后停止 |
| 缩放层没有声明 `will-change` | 放大开始那一刻才临时建图层、按放大后尺寸重新栅格化整张图 | `.bg`、`.fg` 声明 `will-change: transform` |
| 图片可能还在解码就开始转场 | 第一帧现场解码 | `await img.decode()` 后才允许进门 |

### 6.3 以后加效果要守的规矩

1. **动画只改 `transform`（含 `translate`/`scale`/`rotate`）和 `opacity`。**
2. **会动的图层里，以及会动的图层上方，不要用** `mix-blend-mode`、`filter`、`backdrop-filter`、`box-shadow` 动画、`background-*` 动画。
3. **不要动画** `width`、`height`、`top`、`left`、`margin`、`background`。
4. **大图层提前声明** `will-change: transform`，但只加在确实会动的大元素上。给几十个小元素都加，反而占显存。
5. **静止时不要跑 `requestAnimationFrame`。**
6. **程序生成的纹理（噪点、复杂渐变）预渲染成图片。**

### 6.4 怎么自己排查卡顿

Chrome 开发者工具：

- **Performance 面板**：点录制，做一次转场，停止。看帧条里有没有红色长条，点开看是 "Paint"（绘制）还是 "Composite"（合成）占时间。转场过程中应该几乎只有 Composite。
- **Rendering 面板**（按 Ctrl+Shift+P 输入 "Show Rendering"）：勾选 **Paint flashing**，重绘的区域会闪绿色。转场时整屏闪绿就说明有属性在触发重绘。
- **Layers 面板**：确认 `.bg`、`.fg` 各自是独立图层。

**演示电脑一定要实测一次。** 集成显卡、外接投影仪、Chrome 的"使用图形加速"被关掉，都会让性能明显下降。Chrome 地址栏输入 `chrome://gpu`，确认 "Compositing" 是 "Hardware accelerated"。

## 7. 集成到 React + Vite

### 7.1 素材放哪里

```
web/src/assets/scene/
  gate-fg.webp
  temple-bg.jpg
  grain.png
web/src/components/TempleScene.tsx
web/src/components/TempleScene.css
```

放在 `src/assets` 里并用 `import` 引用，Vite 会自动加哈希，缓存更新不会出问题。CSS 里的 `url('../assets/scene/grain.png')` Vite 也会自动处理。

### 7.2 组件拆分建议

**场景组件只负责画面，不管业务。** 它只接收一个 `view` 属性，业务页面负责决定当前是哪个 `view`。

```tsx
// TempleScene.tsx
import { useEffect, useMemo, useRef } from 'react';
import fgUrl from '../assets/scene/gate-fg.webp';
import bgUrl from '../assets/scene/temple-bg.jpg';
import './TempleScene.css';

export type SceneView = 'gate' | 'passing' | 'inner';

const reduce = typeof matchMedia !== 'undefined'
  && matchMedia('(prefers-reduced-motion: reduce)').matches;

type PetalOpts = { n: number; x0: number; x1: number; s0: number; s1: number;
                   t0: number; t1: number; y0: string; y1: string };

function makePetals(o: PetalOpts) {
  const r = (a: number, b: number) => a + Math.random() * (b - a);
  return Array.from({ length: o.n }, () => ({
    left: `${r(o.x0, o.x1)}%`,
    '--s': `${r(o.s0, o.s1)}px`,
    '--t': `${r(o.t0, o.t1)}s`,
    '--d': `${-r(0, o.t1)}s`,
    '--y0': o.y0, '--y1': o.y1,
    '--dx': `${r(-8, 14)}vw`,
    '--rot': `${r(180, 540)}deg`,
  }) as React.CSSProperties);
}

export function TempleScene({ view }: { view: SceneView }) {
  const bgRef = useRef<HTMLDivElement>(null);
  const fgRef = useRef<HTMLDivElement>(null);

  // 花瓣参数只生成一次；用 JSX 渲染，而不是 appendChild（StrictMode 下会生成两遍）
  const back  = useMemo(() => reduce ? [] : makePetals({ n: 22, x0: 30, x1: 66, s0: 5, s1: 9, t0: 9, t1: 15, y0: '30vh', y1: '80vh' }), []);
  const front = useMemo(() => reduce ? [] : makePetals({ n: 7, x0: 0, x1: 90, s0: 16, s1: 24, t0: 7, t1: 11, y0: '-10vh', y1: '110vh' }), []);

  // 鼠标视差：直接改 DOM，不经过 React state（否则每帧都会重新渲染组件）
  useEffect(() => {
    if (reduce) return;
    let tx = 0, ty = 0, cx = 0, cy = 0, raf = 0;
    const tick = () => {
      cx += (tx - cx) * 0.08; cy += (ty - cy) * 0.08;
      bgRef.current!.style.translate = `${(cx * -12).toFixed(2)}px ${(cy * -6).toFixed(2)}px`;
      fgRef.current!.style.translate = `${(cx * -34).toFixed(2)}px ${(cy * -14).toFixed(2)}px`;
      raf = Math.abs(tx - cx) + Math.abs(ty - cy) > 0.0005 ? requestAnimationFrame(tick) : 0;
    };
    const onMove = (e: PointerEvent) => {
      tx = e.clientX / innerWidth - 0.5; ty = e.clientY / innerHeight - 0.5;
      if (!raf) raf = requestAnimationFrame(tick);
    };
    addEventListener('pointermove', onMove);
    return () => { removeEventListener('pointermove', onMove); cancelAnimationFrame(raf); };
  }, []);

  return (
    <div className="scene" data-view={view} aria-hidden="true">
      <div className="stage">
        <div className="layer bg" ref={bgRef}>
          <img src={bgUrl} alt="" decoding="async" />
          <div className="sun-wrap"><div className="sun" /></div>
          <div className="petals">{back.map((s, i) => <div className="petal" style={s} key={i}><i /></div>)}</div>
        </div>
        <div className="layer fg" ref={fgRef}>
          <img src={fgUrl} alt="" decoding="async" />
          <div className="glow l" /><div className="glow r" /><div className="glow c" />
          <div className="dapple-wrap"><div className="dapple" /></div>
        </div>
        <div className="petals front">{front.map((s, i) => <div className="petal" style={s} key={i}><i /></div>)}</div>
      </div>
      <div className="grain" />
      <div className="shade vignette" />
      <div className="shade dim" />
    </div>
  );
}
```

CSS 直接从 `index.html` 的 `<style>` 里复制，改两处：

1. 状态选择器从 `body[data-view="inner"] .fg` 改成 `.scene[data-view="inner"] .fg`，其他同理。
2. 加一个外层容器，把场景固定在最底层：
   ```css
   .scene { position: fixed; inset: 0; z-index: 0; overflow: hidden; background: #151821; }
   .scene .grain, .scene .shade { position: absolute; }   /* 原来是 fixed，放进 .scene 后改为相对它 */
   ```

`.ui`、`.plaque`、`.card`、`.btn` 这些是 demo 里的示意界面，正式界面按 02 设计文档的视觉规范做，放在场景之上即可。

### 7.3 和业务视图对应

02 设计文档定义了五种视图：输入、等待、支线、回望、收据。场景只有门外、门内两个状态，对应关系是：

| 业务视图 | 会话状态 | 场景 `view` |
|---|---|---|
| 输入 | 无会话 | `gate` |
| 等待（刚提交） | `generating` | `passing`，1.5 秒后自动变 `inner` |
| 等待（AI 还没回来） | `generating` | `inner`，显示等待提示 |
| 支线 / 回望 / 收据 | `ready` / `reflecting` / `ending` / `complete` | `inner` |
| 错误 | `error` | `inner`，显示错误信息 |
| 重新开始 | 调用 `POST /api/reset` 之后 | `gate` |

也就是说：**点"看看另一条路"提交表单时穿门，点"重新开始"时回门口，中间所有页面都在门内切换。** 门内各页面之间用普通的卡片淡入淡出就够了，不要每次都穿门。

```tsx
const [sceneView, setSceneView] = useState<SceneView>('gate');

async function onSubmit(input: Input) {
  setSceneView('passing');
  setTimeout(() => setSceneView('inner'), 1500);
  // 同时发请求，不必等动画结束；AI 通常比 1.5 秒慢
  // 请求体按 contracts/types.ts 的 CreateSessionRequest，细节见 05-后端交接-给前端.md
  const res = await fetch('/api/sessions', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ requestId: crypto.randomUUID(), mode: 'live', input }),
  });
  // ...开始轮询 GET /api/sessions/{id}
}

async function onRestart() {
  await fetch('/api/reset', { method: 'POST' });
  setSceneView('gate');
}
```

几点注意：

- **转场和请求并行。** 不要等动画播完再发请求，也不要等请求回来再播动画。
- **AI 很快就返回时**，也要等 `inner` 之后再显示故事卡片（可以记一个"转场结束"标志，两个条件都满足才显示），否则卡片会在门框还没散开时就冒出来。
- **1.5 秒的定时器**要在组件卸载或 `onRestart` 时清掉，理由同第 5 节。
- **首次进门前等图片解码**：场景组件挂载时对两张图调用 `img.decode()`，提交按钮在解码完成前可以先禁用，或者像 demo 一样 `await` 后再切状态。输入页用户要填表，通常早就解码完了。

### 7.4 长文本滚动

demo 里 `body` 是 `overflow: hidden`，因为只有一张小卡片。正式版的故事正文会很长，02 文档要求正文区可滚动。

做法：场景 `position: fixed` 固定在底层（第 7.2 节已经这么写了），界面层单独滚动。

```css
.content-layer {
  position: relative; z-index: 1;
  height: 100vh; overflow-y: auto;
  padding: 16px;
}
```

**不要让整个页面滚动带着场景一起动。** 场景固定不动，只有文字卡片滚动。

### 7.5 字体和可读性

- 门内的文字卡片放在 `.shade.dim` 压暗之后的区域（屏幕下半部分），对比度才够。卡片要放上半部分的话，需要把 `.shade.dim` 的渐变方向调整一下。
- 牌匾标题用了楷体（`STKaiti`、`KaiTi`），这是系统自带字体，不需要下载。正文和按钮不要用楷体，02 文档有要求。

| 想调整 | 改哪里 | 当前值 |
|---|---|---|
| 转场总时长 | `.fg` / `.bg` 的 `transition: scale 1.8s` | 1.8 s |
| 何时显示内页 | JS 的 `T_PASS` | 1500 ms |
| 穿门力度 | 门内状态的 `.fg { scale }` | 2.8 |

| 视差幅度 | `tick()` 里的 `-12 / -6`（背景）和 `-34 / -14`（前景） | — |
| 视差跟手程度 | `tick()` 里的 `0.08`，越大越跟手 | 0.08 |
| 灯火亮度 | `.glow` 的 `radial-gradient` 透明度 | .5 |
| 灯火节奏 | `.glow` 的 `animation: breathe 3.4s` | 3.4 s |
| 颗粒强度 | `.grain { opacity }` | .22 |
| 花瓣数量 | `spawn()` / `makePetals()` 的 `n` | 远 22，近 7 |
| 内页压暗程度 | `.shade.dim` 的渐变 | 底部 .8 |

调参数时注意：视差幅度加大后，背景层的初始 `scale: 1.06` 可能不够，边缘会露出深色底，要同步加大。

## 9. 常见问题

**转场还是卡。** 先按第 6.4 节检查演示电脑的硬件加速。其次检查是不是新加的效果违反了第 6.3 节的规矩。实在不行可以关掉樱花（最多的动画元素）或者把前景放大倍数降到 2.2。

**门框边缘露出白边或深色边。** 视差或放大时背景没盖住。加大 `.bg` 的初始 `scale`，或者减小视差幅度。

**光晕没对准灯笼。** 检查 `.stage` 的宽高比是否还是 1671:941。如果改了容器尺寸写法，百分比坐标就对不上了。

**按 D 看到大殿有重影。** 背景图和前景没对齐，通常是替换了 GPT 图但没重跑 `make_layers.py`，或者 GPT 移动了画面。见第 2.3 节。

**开发时花瓣数量翻倍。** React StrictMode 会让 effect 执行两次。用第 7.2 节的写法（`useMemo` 生成数据 + JSX 渲染），不要在 effect 里 `appendChild`。

**视差时组件疯狂重新渲染。** 鼠标位置不要放进 `useState`，按第 7.2 节用 `ref` 直接改 DOM。

**演示时动画全都不动。** 演示电脑开了"减少动态效果"，见第 4.8 节。
